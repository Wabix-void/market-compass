## 二、技术栈与工程特点

- **零第三方依赖**：后端与数据处理全部使用 Python 标准库（`http.server` + `sqlite3`），前端为原生 HTML/CSS/Canvas，无 CDN 依赖。评审无需安装任何包，两条命令即可在本地复现全流程。
- **开源（MIT）**：项目**自身以 MIT 许可证开源**（见 `LICENSE`），可自由使用、修改、分发与商用。需要特别说明的是："零第三方依赖"**不是**指不用开源技术，而是指**运行时不依赖任何第三方包** —— 这让整条数据链路可以被逐行审计，评审不需要信任任何黑盒。
- **分层架构**：接入层 / 存储层 / 计算层 / AI 层 / 应用层。每种数据源只需实现一个适配器，产出统一的原始层格式，下游 ETL、指标、AI、看板零改动。
- **可追溯**：原始层保留不可变快照，指标层可由原始数据全量重算；每条 AI 结论可下钻到具体指标与采集批次。**审计台账跨数据重建保留**，采集历史不会被下一次重建抹掉。
- **可验证性优先**：把"签名对不对""证据链是否成立""版式有没有溢出"都变成 30 秒内能跑出来的自动化检查，而不是靠人工确认。

## 三、差异化：与通用大模型、现有工具的本质区别

| 对比对象 | 它们的做法 | 本项目的做法 |
|---|---|---|
| **通用大模型**（直接问"卖什么好"） | 直接生成结论，数字随口就来、无法核验 | 数值**只能**来自指标层；每条结论生成后回指标层**逐条重算**（相对容差 0.5%），任一条复现不出，整份报告降级为"数据不足" |
| **现有电商数据工具** | 给表格和图表，结论靠人自己看 | 直接给带证据链的判断与建议动作，每条动作绑定一个可复现指标 |
| **灰产式数据抓取** | 逆向 App 接口、绕过签名与验证码 | 公开数据 + 官方授权接口 + 用户授权导入；robots 明确禁止的平台直接不抓，采集行为全部登记审计 |
| **传统爬虫报表** | 只报"抓到了多少条" | 每个数字都带**数据口径与置信度**；观测不到增量时降级并降低置信度，而不是输出 0 |

一句话概括：**其他 AI 选品工具让大模型直接生成结论，因此会编；本项目要求每条结论必须能回指标层重算复现，编不出来就整体降级为「数据不足」。**

这是**架构层面**的约束，不是提示词层面的祈祷。

## 四、数据合规声明

本作品只使用**公开可访问数据**与**平台官方授权接口**：

- 采集前读取并遵守 `robots.txt`；**特别识别了"robots.txt 被返回成首页 HTML"这一陷阱**——常见的 `urllib.robotparser` 在解析失败时会默认放行，若不核对响应内容，会把违规抓取误判成合规。本项目对此做显式检测并保守放弃。
- 默认限速 **3 秒/请求**，不并发、不重试轰炸。
- **不采集任何个人信息**：无用户 ID、无评论正文、无联系方式；评论仅做聚合情感与关键词统计。
- 不绕过登录、验证码与任何风控机制；robots 明确禁止的平台（如淘宝、唯品会的搜索页）**直接不采集**。
- 每次采集写入审计台账，记录来源、URL、时间、robots 判定、字段范围与批次号；审计记录**跨数据重建保留**。

## 五、数据源可信度分级

系统对每一类数据源都定义了明确的指标口径与置信度上限，**换数据源不改变机制，只升级口径**：

| 数据源 | 可获取字段 | 指标口径 mode | 置信度上限 |
|---|---|---|---|
| 官方开放平台 API（淘宝 / 京东 / 拼多多） | 真实销量、价格、类目、库存 | `api_volume_direct` | **0.85** |
| 公开页面（≥2 天，评价增量 > 0） | 评价数、榜单排名、店铺类型 | `review_increment_basis` | 0.46 |
| 公开页面（仅 1 天） | 同上 | `single_snapshot_stock_basis` | 0.46 |
| 公开页面（增量不可观测） | 同上（评价数为缓存展示值） | `review_increment_stale_stock_fallback` | 0.40 |
| 完整公开信号（有已售件数增量） | 已售件数、评价数、排名、价格 | `full_signal` | 0.96 |

三点必须说明的差异：

1. **滚动销量 ≠ 累计销量**：官方接口返回的是"近 30 天销量"这类滚动窗口值。若当累计值相减会得到无意义的数，因此系统用 `sales_semantics` 标记把这类数据隔离，只作规模值使用，不参与增量推算。
2. **平台之间的精度差异**：淘宝 `volume` 返回具体数字；拼多多 `sales_tip` 返回"1万+"这类区间提示。申请凭据时应优先选择返回精确值的接口。
3. **换源不改机制**：无论数据来自公开页还是官方 API，口径、置信度、证据链都保持透明可追溯——这才是可信度的真正保障。

> **实测记录（2026-10-15 / 10-16 两轮真实采集）**：66 个商品两日的评价数**一个都没变**——
> 苏宁公开页展示的是缓存值（如"9000+"），一天间隔观测不到增量。系统因此退化为存量估计，
> 置信度从 0.46 进一步降到 0.40，而不是输出一堆 0。要观测真实增量，需要更长的采集间隔（建议 ≥1 周），
> 或改用官方开放平台 API。

## 七、诚实声明：已知限制

我们认为把限制讲清楚比包装成完美更重要：

1. **没有"真实销量"**：公开数据在任何非官方渠道都拿不到平台真实销量。系统输出的是销量代理指标，并明确标注口径与置信度，不使用"真实销量"这类表述。
2. **公开页评价数是缓存值，日级增量不可观测**：两轮实测中 66 个商品的评价数毫无变化，因此系统退化为存量口径（置信度 0.40），环比显示为"不可用"而非 0%。
3. **价格字段缺失**：苏宁搜索页的价格由 JS 异步加载，静态采集拿不到，报告中标注为"价格未采集"，销售额估计标记为不可用。
4. **官方 API 未经真实凭据验证**：签名与字段映射按各平台公开文档实现，并配有配置向导与 `--live` 自检脚本；实际参数需拿到凭据后校准。
5. **AI 默认运行在离线模板模式**：交付状态下不调用外部大模型（`llm_provider = offline-template`），建议由规则与模板生成、证据链校验保证可靠性。配置 `MARKETCOMPASS_LLM_*` 环境变量即可切换为真实模型，届时模型仅负责把已算好的指标组织成自然语言，仍不参与数值生成。
6. **覆盖范围有限**：目前真实数据源仅苏宁易购（其余主流平台的公开搜索页有反爬或 robots 禁止）。

## 九、可持续演进与生态价值

**演进路线**

1. **短期**：启用官方开放平台 API 补齐真实销量与价格；增加"用户粘贴页面 / 浏览器书签"方式采集长尾站点（不依赖 appkey，已有架构可直接扩展）。
2. **中期**：Agent 化自动生成《某品类市场机会研究报告》；支持商家后台报表授权导入。
3. **长期**：沉淀行业级商情数据库，输出类目指数与趋势预测。

**可复用性**

- **适配器架构**：新增数据源只需实现一个适配器（约 100 行），产出统一的原始层格式，下游 ETL / 指标 / AI / 看板**零改动**。目前已有三类适配器（公开页面、官方 API、演示数据）落地验证。
- **口径规范可复用**：五种数据口径 + 置信度上限的设计，可作为同类"公开数据 + AI 结论"项目的参考规范——尤其是"观测不到增量时降级而不是输出 0"这一条，避免了许多数据产品用 0 掩盖数据缺失的问题。
- **证据链机制可移植**：把"结论必须能回数据层重算"做成可插拔的校验器，任何"数值 + 语言模型"的组合都能复用。

**生态与合作价值**

- 可与电商服务商 / 代运营合作，把选品分析作为其服务包的一环（接口已就绪，批量选品 API 是明确的下一步）
- 可与高校电商、消费研究方向合作，提供可复现、口径透明的公开数据指标集
- **MIT 开源**（见 `LICENSE`），允许二次开发与商用，便于形成社区适配器生态——每接入一个新平台，就是一个可独立贡献的适配器
